# AV Monitor — Telegram-бот мониторинга объявлений av.by

Python 3.11+, aiogram 3, SQLite (stdlib). Реализовано всё из ТЗ: обязательная подписка на канал, главное меню,
FSM-мастер фильтров, разовый поиск, отслеживание продавца, «Мои мониторинги» (пауза/удаление), «Стоп все»,
лимит бесплатного тарифа + Premium, рассылка, `/stats`.

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # заполните BOT_TOKEN, ADMIN_IDS, CHANNEL_ID
python -m avbybot.check_api     # ОБЯЗАТЕЛЬНО перед первым запуском (см. ниже)
python -m avbybot
```

Бот должен быть **администратором** канала подписки — иначе Telegram не даст проверить участников
(в этом случае проверка отключается и в логе пишется ошибка). Пустой `CHANNEL_ID` отключает проверку.

## ⚠️ Что проверить первым делом

Формат данных av.by не документирован. Код написан по описанию неофициальных точек входа
(`api.av.by/...` и данные в `__NEXT_DATA__` страницы `cars.av.by/filter`), но **на живом сайте при разработке
он не запускался** (в среде разработки не было доступа в интернет). `python -m avbybot.check_api` за пару секунд
покажет: какой источник сработал, какие поля разобраны, отсортирована ли лента «новые сверху» (иначе подберите
`AVBY_SORT`), доступен ли каталог марок. Если что-то не так — правится только `avbybot/parsing.py`
(`normalize`) и константы в `avbybot/avby.py`; остальной код от формата сайта не зависит.

Отдельно не проверены на реальном Telegram: хендлеры aiogram прогнаны на заглушках (весь мастер, лимиты, поиск,
список мониторингов), ядро (разбор, фильтры, БД, цикл) покрыто тестами: `python tests/test_core.py`.

## Как это работает

* **Одна лента на всех.** Раз в `POLL_INTERVAL` сек бот забирает 1–`MAX_PAGES` страниц самых свежих объявлений и
  проверяет каждое новое по всем активным мониторингам. Число запросов к av.by не растёт с числом пользователей.
* **Первый проход.** Всё, что бот увидел, записывается в `seen_adverts`. При самом первом запуске бот только запоминает
  ленту. Мониторинг реагирует лишь на объявления, опубликованные после его создания (запас 60 с на расхождение часов).
* **Без дублей.** Пара (мониторинг, объявление) занимается в `sent_adverts` до отправки; пересекающиеся
  мониторинги одного пользователя дают одно уведомление.
* **Фильтры** сравниваются локально (`matcher.py`): марка/модель, регион, год, цена в USD/BYN, топливо, КПП, кузов,
  минус-слова (подстрока без учёта регистра: «бит» найдёт «битый»/«битая»). Если регион объявления определить не
  удалось, оно не отсекается.
* **Продавец:** ссылка на любое его объявление (ищется id продавца) или название. По названию совпадают и тёзки —
  для частных лиц надёжнее id.
* **Лимиты:** `FREE_LIMIT` активных мониторингов; Premium и админы — без лимита.

## Админ

`/admin` · `/stats` · `/broadcast` (любое сообщение, подтверждение, отчёт) ·
`/premium <user_id> <дней>` (0 — снять; пользователь должен хоть раз нажать /start).

## Структура

```
avbybot/
  main.py  config.py  context.py  db.py          сборка, настройки, SQL
  avby.py  parsing.py  matcher.py  models.py     клиент av.by, разбор, фильтры
  monitor.py  notify.py  formatting.py           цикл мониторинга, отправка, тексты
  subscription.py  keyboards.py  utils.py
  handlers/  start · wizard · monitors · seller · admin · fallback
tests/test_core.py
```

## Что дальше

PostgreSQL — переписать `db.py` (весь SQL там); состояние мастера хранится в памяти (`MemoryStorage`, при
перезапуске теряется) — для продакшена подключите Redis-хранилище aiogram; оплата Premium (например, Telegram
Stars) — вместо ручной команды `/premium`; webhook вместо long polling. Соблюдайте правила av.by и не
уменьшайте интервал опроса без необходимости.
